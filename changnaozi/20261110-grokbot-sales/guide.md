# 用 Grok Bot 搭全自动销售工作流 - 微信

> 攻略摘要（非逐字稿）。源：微信公众号「萍姐学业成长圈」《Grok Bot 全自动销售教程》（2026-11-03）。  
> **口径提醒**：文中套餐明细/Shared Bots 可用性来自**第三方整理**，下单前以官方为准。Webhook、单 Bot routine 上限（文称最多 50、保留 20 条运行记录）、演示录制约 10 分钟上限等，文内已标明 **xAI/官方未公布或需实测**——本文攻略亦照此标注，不作官方承诺。

## 一句话定位

把销售杂活（会前简报、读纪要、CRM 预览更新、晨报）交给共享 Grok Bot 自动跑；金额、合同、对外沟通一律人审——「全自动」只覆盖可定义标准的部分。

## 上手顺序

1. **确认资格**：X Premium/Super/Ultra 或 Cursor 付费 / Teams；共享 Bot 需 Teams/Enterprise 公测能力，且 Bot **必须跑云端**（本地不可共享）。套餐以官方为准。
2. **一句话职责建 Bot**：有范围+边界（例：「12 个账号的会前准备与会后更新，对外只起草不发送」），忌「处理销售相关事情」。
3. **喂 Context 三层**：产品品牌（稳）→ 流程规则（季更）→ 客户账号（变）；第 3 层从 CRM **实时读**，勿写死进文件。
4. **接 Plugins**：销售最小组合优先 Salesforce + Slack；邮件与会议记录强烈建议；无插件再用 Credentials 调 API。国内可用纷享销客/飞书等替换方法论不变。
5. **先固化 Skill，再谈 Routine**：先手动跑稳 → 存 Skill → 再定时/触发。顺序反了只会批量产垃圾。
6. **上第一个低风险 Routine**：如每天 08:30 北京时间账号晨报；强制「无变化就写无变化」。
7. **共享前安检**：插件/密钥/skills/文件只放愿意全员共用的；指定一人每周复查团队记忆。
8. **硬边界写进 Skill**：金额只读、不代发邮件、不代提折扣审批——不要只靠 Auto-review。

## 能力表：什么能自动 / 半自动 / 不能自动

| 环节 | 模式 | 谁做 |
|---|---|---|
| 客户调研 | ✅ 全自动 | Bot |
| 会前简报（定时） | ✅ 全自动 | Bot |
| 读会议记录 | ✅ 全自动 | Bot |
| 更新 CRM 字段 | ⚠️ 半自动 | Bot 出预览，人确认后写 |
| 跟进邮件 | ⚠️ 只起草 | Bot 写，人发 |
| 报折扣 / 非标条款 | ❌ | 人工审批 |
| 客户沟通 | ❌ | 人 |

## 可复制提示词 / 金句（完整版见逐字稿）

逐字稿已完整保留 4 条 Skill + 1 条晨报 Routine，此处只列用途索引：

1. **Skill 1 会前简报**：5 段事实结构；禁建议/成交概率预测；无来源写「未查到」。
2. **Skill 2 会后 CRM 更新**：先预览表再写；金额与成交日期只读；不建新商机。
3. **Skill 3 跟进邮件草稿**：≤150 字；确认理解/下一步/责任人；**永远不发送**。
4. **Skill 4 折扣前自查**：查权限与同类历史区间；**禁止代提交审批**。
5. **Routine 晨报范例**：08:30 → Slack；变化 + 今日一件事 + 理由；无变化不硬凑。

金句：

- 「凡是没法清晰定义判断标准的决策 / 面向客户的沟通，要求人工审核。」
- 「先把一个任务做可靠，再存成 Skill，最后才谈自动化。」
- 「销售代表不能用报价 Bot 批准自己的折扣。」
- 「共享的是知识，不是会话。」
- 「审批不是硬边界」——金额/合同/对外发送要在 Skill 写死。

## 三个销售 Bot 配置清单（抄作业）

| Bot | 职责一句话 | 关键 Skills / Routine | 硬边界 |
|---|---|---|---|
| A 客户情报 | 会前准备 + 会后更新 | Skill 1/2；08:30 晨报；会后更新商机 | 金额字段只读 |
| B 报价助手 | 多套报价对比 | Skill 4 | 不代提交审批；不批自己的折扣 |
| C 条款审核 | 非标条款对照已批口径 | （建议类输出） | 只出建议等人批；留痕「决策+理由+负责人」 |

## 坑

- 职责太宽 → 一个 Bot 一个岗位。
- 动态客户数据进文件 → 过期；改 CRM 实时读。
- 先自动化后固化 → 垃圾加速；顺序：可靠 → Skill → Routine。
- 晨报无「无变化」禁令 → 每天 12 条废话。
- 个人密钥给团队 → 改专用只读最小权限 key。
- 只靠审批 → 无人应答可能静默放行（文称企业版可强制）；硬边界写进 Skill。
- 共享记忆无人复查 → 错事实全队传播。
- 本地 Bot 想共享 → 必须云端。
- Auto-review / 提示注入：官方口径是减弱风险，不消除；外部内容当不可信。
- 删除共享 Bot 不可撤销，连带同事聊天与 routine；审计日志多属企业版。

## 适合谁

- 已有/准备上 Grok Bot（含共享）的销售或 RevOps，愿意把杂活标准化。
- 有 CRM + 即时通讯（Salesforce/Slack 或国内等价）可接插件或 API。
- **不适合**：指望「连客户邮件都自动发」、把折扣审批交给 Bot、或尚无稳定人工流程就上全自动的人。
