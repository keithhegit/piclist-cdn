# Codex 前端去 AI Slop：AGENTS.md 微文案禁令 - 抖音

> 一句话定位：把「禁止次要标签 / 说明文字 / 辅助文案 / 冗余微文案」写进 `AGENTS.md`，逼 Codex（及同类 Agent）用布局与层级自解释，而不是堆 AI Slop 说明句。  
> 源：小石谈记（AI版）《怎么让codex设计前端更优雅》· https://www.douyin.com/video/7703495942707694882 · 约 1:46 · 2026-11-02

## 上手顺序

1. 在项目根（或 Agent 会读到的目录）打开 / 新建 `AGENTS.md`。
2. 粘贴下方「可复制提示词全文」（成片屏幕版）。
3. 用 Codex / Claude Code 等会读 `AGENTS.md` 的工具改 UI；优先改设置页、表单、卡片列表这类最爱堆小字的界面。
4. 对照「mute test」：去掉说明句后，新人是否仍知道下一步点哪里；不行就改布局/主按钮文案，而不是加回小字。
5. 危险操作仍保留后果提示；表单标签与可访问名称不要砍。
6. （可选）大改动会话结束前按「收尾」派最强模型子代理做一次 code review，并在 `progress.txt` 记一行。

## 可复制提示词全文（成片屏幕 `AGENTS.md`）

> 以下按成片 FloatDo 窗口内打开的 `AGENTS.md` 可见正文收录（约 01:10–01:35 多帧）。不要改写成第一人称口播。

```markdown
## 工作原则

- 前端质感与丝滑动效是核心要求。涉及到前端的改动，可以多轮截图验收打磨。
- 代码开发不重复造轮子，可以并建议参考对应成熟项目的源代码。
- 不做过度开发，以优雅为原则，以用户体验为第一性原理。

## 前端原则

- 避免不必要的次要标签、说明文字、辅助文案、描述性文字和冗余的微文案，让布局、视觉层级、间距和清晰的主操作自己完成解释。
- 具体要求：
  - 优先用强视觉层级和自解释的结构，而不是用文字去解释。默认不要添加 slogan 式文字、教学段落，或在每个区块下都加「帮助说明」。如果确实需要补充信息，优先使用 info 图标 + tooltip，而不是始终显示的次要文字。
- 保留必要的表单标签和可访问名称。界面清爽不能牺牲可访问性。
- 危险或不可逆操作（删除、支付、提交永久性变更）必须保留清晰的后果提示。
- 去掉说明文字后，第一次使用的人仍应能看懂：下一步点哪里、点了会发生什么。
- 重写已有界面时：先去掉冗余标签和说明，如果清晰度下降，再优化布局和按钮文案。

## 收尾

- 每轮涉及较大代码改动的会话，在最终交付前，派出使用当前可用最强模型的独立子代理进行代码 review；随后由主代理接力修复有效问题并验证。一轮对话通常只 review 一次，确有必要才复审，避免重复迭代。
- 有实质进展时，在根目录 `progress.txt` 追加一行：`[YYYY-MM-DD HH:mm] [完成的主要内容]`，保持简短。
```

## 坑

- **只写「要高级 / 要优雅」没用**：作者与评论都强调要写清「不能加」的具体文案类型（次要标签、说明、辅助文案、微文案）。
- **别误砍必要标签**：表单标签、accessible name、危险操作后果提示必须留；第三方评测也提示「Cut helper text」可能误伤错误提示。
- **清爽 ≠ 无障碍**：界面变干净后仍要用 mute test 检查首用是否看懂。
- **工具要读得到文件**：提示词放进 Agent 实际会加载的 `AGENTS.md` / 等价规则文件；只贴聊天一次性提示容易丢。
- **产品名口误**：口播 ASR 易听成 Flow stew / Flows Duo；画面产品是 **FloatDo**（灵动岛便签）。
- **英文两行 ≠ 屏幕文件**：屏幕是中文扩写 `AGENTS.md`；英文是 X 灵感源。
