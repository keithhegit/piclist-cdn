## 上手顺序

1. **承接 Ep1**：已接受「别追已爆」后再读本篇特征，否则容易只收藏概念。
2. **反常现象先记**：高 CCU / 高 Favorites ≠ 适合做站；escape 类单动作往往只有 codes。
3. **对照四特征**过候选游戏：机制密度 → 可搜索问题 → 价值体系 → 生态起势过程。
4. **用文末「值得提前布局」五条清单**做门禁，不达标就观察不投入。
5. **记住时间窗口**：先有玩家问题，后有搜索，最后才是站；窗口内上站才有意义。
6. **进 Ep3**：把信号变成可记录、可计算的指标 + 开源评估器。

## 能力表

| 特征 | 含义 | 例子（文中） | 可迁移检查 |
|---|---|---|---|
| 机制密度 | 持续选择/收集/比较/优化 | Grow a Garden 种子突变宠交易；Fisch 竿饵地点变体 | 玩家是否必须查外部工具/Wiki？ |
| 可搜索问题 | 火≠能写站；要有 How/Tier/Value/Calc/DB | How to get / Tier List / Value / Calculator / Database | 除 codes 外能否列出问题类型？ |
| 价值体系 | 交易、稀有度、市价、排行 | 「值多少/亏了吗/最强吗」类长期需求 | 有无比较与估值，而不只是升级？ |
| 爆发有过程 | 非突然火；讨论从「是什么」到「哪个最好」 | YT 多创作者、更新后峰值抬升 | 是否进入深度使用阶段？ |
| 时间窗口 | 问题→搜索→SEO 滞后 | 文末核心发现 | 是否仍处搜索尚未挤满的窗口？ |

**值得提前布局的画像（文末压缩）**：持续增长楼梯｜大量可枚举对象｜有比较决策｜有传播钩子｜有持续更新。

## 可复制点

1. **反例**：平台很火但无信息外溢 → 广告费可能回不了域名。
2. **问题→页面映射**：怎么获得→How to get；哪个最好→Tier；值多少→Value；概率→Calculator；有哪些→Database。
3. **SEO 本质表述（文意）**：解决已存在问题 / 迎合意图，不是凭空造内容。
4. **样本范围**：文中列 Grow a Garden、Steal a Brainrot、Fisch、Dead Rails、Blox Fruits 等 + 反例对照。
