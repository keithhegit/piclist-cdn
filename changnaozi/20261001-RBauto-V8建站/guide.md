## 一句话定位

公众号「七鹿AI」展示自研 **RBauto / RB Auto V8**：用搜索意图设计站点结构、从 Wiki/视频/社区抽具体数值做实内容、以玩家能否完成任务验收的 Roblox 游戏 SEO 站全自动 Agent；案例站 AnimeDice.org + 产品页定价晒图，读它是为了**抄方法骨架与验收标准**，不是免费开源教程。

## 上手顺序

1. **先认清体裁**：这是产品迭代晒单（图文轮播 + 短文案），不是逐步手把手课；价格与流量为账号展示。
2. **对齐痛点**：是否也在做「关键词很多、页面很多、但玩家仍不知道怎么操作」的薄内容站。
3. **抄三条流水线骨架**（不必买工具也能自建 Agent 流程）：
   - 搜索意图 → 决定首页模块与内页关键词焦点
   - 资料源（Wiki / 视频 / 社区）→ 抽数值、步骤、适用条件
   - 玩家任务能否完成 → 验收（工具/计算器优于空泛介绍）
4. **对照案例站**：打开 AnimeDice.org，看「下一颗骰子怎么买」如何落到规划器（现金 / 收入 / 目标 / 升级对比）。
5. **再决定是否碰商业工具**：若已会 AI 做站、要批量测更多 Roblox 游戏，再看 RB Auto 交付与报价；域名与模型费另计。

### 可复制：给自建 Agent 的流程约束（据文意改写，非原文提示词）

1. **内页内容验收**
   > 这个关键词对应的玩家真实问题是什么？从 Wiki、视频、社区各至少引用一处具体数值或操作步骤；写清适用条件。禁止只写游戏背景介绍。读者看完必须知道「下一步点哪里/买什么/等多久」。

2. **首页意图设计**
   > 列出玩家搜「{游戏名}」时 Top 3 意图。首页首屏只服务第 1 意图：能直接回答的给答案，需要计算的给工具，需要深读的给攻略入口。其余意图放导航，不要堆成通用 wiki 墙。

3. **任务型工具规格（对齐 Anime Dice 规划器）**
   > 输入：当前档位、目标档位、已有现金、每秒收入；可选：升级成本与升级后额外收入。输出：缺口现金、直存时间、升级优先是否更快、Luck/收益展示增量。明确写「不预测随机抽取结果」。

4. **上线验收三问（对齐七鹿思路）**
   > ① 站点信息架构是否由搜索意图决定？② 每个钱款相关页是否有可执行数字而非空话？③ 目标玩家能否在站内完成至少一件决策任务？

## 坑或注意

- **晒单 ≠ 教程**：无逐步安装/提示词全集；方法可抄，执行细节在产品内。
- **价格与费用**：画面为折扣价；域名、模型 API 等另计——下单前问清当前价与包含范围。
- **流量截图口径**：24h 高 CTR/位次好看，未标明是否含品牌词、国家、是否新站爆发期；勿直接当「保证效果」。
- **规划器边界**：案例明确 **不预测 next pull**；复用时别夸大成「必出货」工具。
- **合规与平台**：Roblox / 广告 / 数据账号「接自有平台」——账号与政策风险自负。
- **Codex 语境**：图中写「在 Codex 里用 RB Auto」，具体 IDE/代理环境以产品说明为准，勿默认等于某一种公开 Agent。
