# 攻略摘要｜Roblox 新词雷达：六步自动化找词与监测流程 - 微信公众号

## 一句话定位

公众号「七鹿AI」系列收官篇：把 Roblox **新词找词**做成可持续跑的**游戏监测雷达**——词库主动搜 + 榜单/群组入口、先验证再存历史快照、程序算增长 + AI 读玩法、输出可执行复扫报告，再按 Codex 三轮交付落地；文末附爆款基因提示词仓库与 RB Auto 上站产品。

## 上手顺序

1. **先拆流程，再选模型**：找游戏 → 核实新游 → 存数据 → 按规则分析 → 输出候选 → 定时复查。每步要有具体结果（链接/创建时间/历史对比/证据/下次查什么）。
2. **第一版不要网页**：先让流程真实跑一轮，产出「有来源、有数据、有判断」的报告；有用了再搬到页面（作者路径：聊清流程 → Hermes 跑 → 飞书日报 → 再建监测站）。
3. **词库六类主动搜**：动作/收集/社交/传播/场景/成长（公开页约 180 组合）；轮换搜索、记已搜过组合；**命中词 ≠ 真有玩法**，后面再验。
4. **多入口合并去重**：关键词 + 榜单扫描 + 开发群组信号；用 **Universe ID** 统一身份，记「首次从哪进来、后来又在哪出现」。
5. **先便宜验证再 AI**：如「创建 ≤90 天且同时在线 ≥30」仅作成本门槛；区分创建时间 / 首次发现 / 正式上线；**追加快照不覆盖**（在线、访问、收藏、投票等）。
6. **程序算数、AI 读玩法**：增长指标程序算；核心动作/奖励/目标由 AI 先抽事实再按固定标准评分（证据 + 未知项）；潜力 / 证据充足度 / 观察阶段分开看。
7. **报告要带下一步**：下一次查什么、何时查、什么变化值得重排优先级；任务失败 ≠ 没有新机会。
8. **Codex 分三轮**：① 真实报告 ② 定时+历史对比 ③ 重点复查与回验；网页只做展示与追溯。
9. **雷达通过后再上站**：值得投入再接 RB Auto；不要雷达高分就批量上站。

## 六步能力表

| 步 | 做什么 | 关键点 |
|---|---|---|
| 1 拆流程 | 找→核实→存→析→出→复查 | 每步有结果；自动化=接流程，不是丢一句「帮我找新词」 |
| 2 词库 | 六类玩法词主动搜 | ~180 组合矩阵；记命中与无效组合；勿把命中数当基因数 |
| 3 多入口 | 搜索 + 榜单 + 群组 | Universe ID 去重合并；群组信号=待验证线索 |
| 4 验证存数 | 门槛筛选 + 历史快照 | 创建/发现/上线时间分开；无历史就标数据不足，失败如实记 |
| 5 分析分工 | 程序算增长，AI 读玩法 | 先事实后评分；Alpha/Confidence/Stage 与网页 A/B/C 勿混为一谈 |
| 6 可执行报告 | 候选 + 下次检查 | 例：Infected Lands 约 4500 在线、12h 后看是否 >6000（当时任务条件，非通用门槛） |
| 持续/回验 | 不同频调度 + 7/14/30 天回验 | 公开配置：关键词 2h / 群组 4h / 新游汇总 6h / 趋势日报；回验约定「何为支持」并留低分对照 |

## 可复制提示词 / 资源

- **游戏爆款基因分析提示词**：开源仓 https://github.com/kennyzir/7deer_skills （拉到最下方）；把 Roblox 游戏链接 + 提示词发给 ChatGPT / Gemini。
- **报告最低字段（候选示例 Crown or Pass，2026-09-01 历史报告口径）**：游戏名、发现来源（如 `party + game`）、创建时间、报告时同时在线、研究等级/评分（当时 B / 79/100）——**非今日实时**。
- **Codex 三轮验收**：报告里的游戏可点开核对来源与数据 → 过一段时间真有多时点记录 → 候选带检查任务且能回核对。

## 坑或注意

- **命中搜索词 ≠ 具备对应玩法**；标题 NEW ≠ 刚上线。
- **公开在线/访问/收藏 ≠ 真实留存或平均时长**（后者需有权限分析）。
- **不要让 AI 猜数据又写玩法再自评**；无历史不要编趋势，采集失败不要填 0。
- **限流/通道降级要写进报告**，勿解释成「今天没机会」。
- **回验设计 ≠ 已完整上线**；网页 A/B/C 等级 ≠ 方案里的 Alpha Index / Confidence / Stage。
- **文末 RB Auto / 加微信为付费产品与社群引流**；「节约半年摸索」是宣传口径，非收益保证。
- 系列前文：原理与潜力信号指标；本篇侧重「如何接成雷达」。

## 适合谁

想把 Roblox（或同类 UGC 平台）**找词从偶发变成持续发现→记录→验证流水线**、愿意先出文本报告再做站的人。不适合：指望一句 prompt 出榜、或雷达打分后直接批量上站不做玩家需求研究的人。
