## C 层 · 二次解读（攻略化 · 非本条口播）

以下压缩自公开二次文与 Anthropic 工程文，供「skill 认知」补全与面试复盘。**勿当作抖音逐字还原。**

### C1. 面试官真正在考什么

- 表层：你会不会写 Skill。  
- 深层：你会不会把**专家经验**变成可复用、可验证、可迭代的系统能力。  
- 挂科答法：「Skill 就是更详细的 Prompt。」

### C2. 一句话定义（可背）

**Skill = 面向某一类任务的可复用能力说明**：何时用、何时不用、怎么做、用什么工具原则、输出何为合格、异常怎么处理。  
Prompt 解决单次表达；Skill 解决跨任务复用。

### C3. 概念边界（高频追问）

| 概念 | 解决什么 | 相对 Skill |
| --- | --- | --- |
| Prompt | 这一次怎么说 | 临场指令 vs 沉淀 SOP |
| Tool | 能不能执行动作 | 执行器 vs 使用指南 |
| MCP | 怎么接到外部系统 | 接入协议 vs 使用策略 |
| Memory | 记得什么事实/偏好 | 知识库 vs 方法论 |
| Harness | 全局编排、权限、注入 | 治理层；应控制 Skill 注入 |

### C4. 高质量构件（九件套精简）

适用 / **不适用** / 输入 / 步骤或决策树 / 工具原则 / 输出格式 / 质量标准 / 失败处理 / 安全边界。  
阿里云同题文额外强调：**专家决策树、反模式、模板示例、验证闭环、失败样本回灌**。

### C5. 何时值得 Skill 化

适合：反复出现 × 复杂 × 有专家判断差 × 输出要稳。  
不适合：一句 Prompt 能说清、纯一次性、无判断含量的杂活。  
**Skill 不是越多越好。**

### C6. 渐进式披露（Anthropic）

1. 启动时只把各 Skill 的 `name` + `description` 放进系统侧。  
2. 模型判断相关后，再读完整 `SKILL.md`。  
3. 需要时再读 `references/`、跑 `scripts/`。  
→ 海量 Skill 时仍可控上下文；与「全塞进 Prompt」对立。

### C7. 选择与治理

- 显式指定 / 描述匹配 / metadata 检索 / Harness 按权限与预算注入。  
- 置信度低则询问；高风险 Skill 要确认。  
- 冲突时优先级：安全规则 > 项目级 > 任务级 > 偏好。  
- 过期 Skill 要淘汰。

### C8. 怎么证明「有用」（面试加分）

不要说「感觉更好」。说指标：任务成功率、工具误用率、格式稳定、人工返工、Token、命中率/误召回；做 **不加载 vs 加载** 的 A/B。

### C9. 常见误区速查

写成长 Prompt；只写步骤不写边界；冲突不管；工具细节写死；不更新；强制全量加载；无 Eval；安全只靠 Skill 软约束。

### C10. 推荐口述链（60–90 秒）

1. 结论：Skill ≠ 更长 Prompt，是可复用能力模块。  
2. 边界：相对 Prompt / Tool / MCP / Memory / Harness。  
3. 结构：至少含适用与不适用、步骤、验收、失败、安全。  
4. 方法：从重复任务与失败案例长出来，进 Eval 闭环。  
5. 治理：按需加载 + 渐进披露，生产里由 Harness 控注入。
